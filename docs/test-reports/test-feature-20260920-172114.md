## Per-Feature Details

### Build image (`docker/Dockerfile.build`)
- **Role:** Downstream user who wants a reproducible Linux build without a local Julia toolchain.
- **Use Case:** `docker build -f docker/Dockerfile.build -t jlw_example-build .`
- **What they tried:** Built on `julia:1.13-bookworm`, installed `build-essential`, instantiated `build-env` and `.`, ran `build.jl`.
- **Discoverability:** Documentation (`docker/README.md` + README "Docker") gives the exact command and states the build image must be built first.
- **Setup:** Pulled `julia:1.13-bookworm`, resolved both Julia environments, compiled with `gcc`.
- **Functionality:** Produced `/app/out/jlw_example.so` (1.72 MiB), `jlw_example.h`, `.abi.json`, `.jlw.json`, `pyproject.toml`, and `jlw_example_py/`. Build finished in ~36 s of Julia work.
- **Expected vs Actual Outcome:** Matched.
- **Blocked steps:** None.
- **Friction points:** None observed.
- **Doc suggestions:** None.

### Python runtime image
- **Role:** Python user with no Julia installed locally.
- **Use Case:** `docker build -f docker/Dockerfile.python -t jlw_example-python . && docker run --rm jlw_example-python`
- **Functionality:** Venv + numpy installed; `PYTHONPATH=out python examples/python/demo.py` printed `Hello, Python`, `scale_inplace -> [0.5 1.  1.5 2. ]`, `escape_time(0.5, 0.5) = 5`, and the Mandelbrot grid.
- **Expected vs Actual Outcome:** Matched the README's documented golden output exactly.

### C++ runtime image
- **Use Case:** `docker build -f docker/Dockerfile.cpp ... && docker run --rm jlw_example-cpp`
- **Functionality:** `g++` compiled `examples/cpp/demo.cpp` against `out/jlw_example.so` with `-Wl,-rpath,/app/out`; ran and printed `Hello, C++`, `scale_inplace -> 0.50 1.00 1.50 2.00`, `escape_time(0.5, 0.5) = 5`, grid.
- **Expected vs Actual Outcome:** Matched.

### Fortran runtime image
- **Use Case:** `docker build -f docker/Dockerfile.fortran ... && docker run --rm jlw_example-fortran`
- **Functionality:** `gfortran` compiled `examples/fortran/demo.f90` (with `-J/tmp`) and ran; printed `Hello, C++`, `scale_inplace ->  0.50  1.00  1.50  2.00`, `escape_time(0.5, 0.5) = 5`, grid. Struct-by-value C returns work with the GCC in the image.
- **Expected vs Actual Outcome:** Matched.

### Rust runtime image
- **Use Case:** `docker build -f docker/Dockerfile.rust ... && docker run --rm jlw_example-rust`
- **Functionality:** Toolchain copied from `rust:1.98.1-bookworm` (matching the repo's Cargo 1.98.1) into the Julia-based image so the `.so` can still resolve `libjulia`; `cargo build` then `cargo run` printed `Hello, Rust`, `scale_inplace -> [0.5, 1.0, 1.5, 2.0]`, `escape_time(0.5, 0.5) = 5`, grid.
- **Expected vs Actual Outcome:** Matched. Lockfile v4 was accepted by Cargo 1.98.1.

### Bundle runtime image
- **Use Case:** `docker build -f docker/Dockerfile.bundle ... && docker run --rm jlw_example-bundle`
- **Functionality:** Stage 1 ran `build_bundle.jl` in the build image; stage 2 is `python:3.11-slim-bookworm` with **no Julia**, `pip install`ed `out-bundle`, and printed `Hello, world`.
- **Expected vs Actual Outcome:** Matched; Julia-independence confirmed by the absence of Julia in the final stage.

## Expected vs Actual Outcome

All five runtime images and the build image built and ran as documented. Every language demo produced the same output as the host-based `run_all.sh`, and the bundle image ran with no Julia present. No expected outcome was missed.

## Issues Found

No blocking or high-severity issues. Minor observations:

1. **Image size.** The Julia-based runtime images are 2.16–2.89 GB each because each derives from the build image (which carries the Julia toolchain). The bundle image is 1.28 GB. This is expected for a demo but could be reduced with a slimmed runtime base or by installing only the Julia runtime closure.
2. **Rust toolchain copy.** `Dockerfile.rust` copies `/usr/local/cargo` and `/usr/local/rustup` from the official image rather than using a shell installer; this is deliberate and keeps the Rust version pinned at 1.98.1.
3. **Docker not available during the earlier doc-only run.** The first test-feature report could not cover Docker; that gap is closed here.

## Blind-Mode Findings

Not applicable — this run exercised the actual Dockerfiles (standard mode). The Dockerfiles are the artifact under test, so handing a doer only prose would not validate them.

## Suggestions

1. Optionally add a `docker compose` file so a single `docker compose build && docker compose up` builds the base image first and then the per-language images, removing the manual two-step ordering requirement.
2. If image size matters, consider a separate slim runtime image that installs only the Julia runtime closure needed by `libjulia` instead of deriving from the full build image.
3. Add a CI job that runs the five `docker run` commands to keep the Dockerfiles from rotting alongside `run_all.sh`.

## Fixes Applied (review-and-fix)

- **Build ordering automated.** Added `docker/Makefile` with `build`, `all`,
  `run-*`, `run-all`, and `clean` targets. `make -C docker all` builds the base
  image before the runtime images; `make -C docker run-all` builds and runs all
  five. Verified: `run-all` printed `Hello, Python`, `Hello, C++` (×2),
  `Hello, Rust`, and `Hello, world`.
  - Gotcha fixed during implementation: the `run-*` pattern targets must not be
    listed as `.PHONY`, or GNU make skips the implicit rule search.
- **Rust image slimmed.** `Dockerfile.rust` now builds the demo in a throwaway
  stage and copies only `jlw-example-demo` into the final image. The image
  dropped from 2.89 GB to 2.16 GB (same as the build image) and still prints the
  full demo output.
- **Docs updated.** `docker/README.md` and the main README "Docker" section now
  document the Makefile workflow and the Rust image behavior.
