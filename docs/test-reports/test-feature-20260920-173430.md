- **Use Case:** `git clone … && cd jlw_example && ./run_all.sh`
- **What they tried:** Ran the block from a fresh checkout of the current working tree (with `.git`, `out/`, `out-bundle/`, `target/` excluded).
- **Discoverability:** Good; the block is copy-pasteable and links to prerequisites.
- **Setup:** Assumed prerequisites present (Julia 1.13, c++, gfortran, cargo, Python3+NumPy).
- **Functionality:** Succeeded. Venv + NumPy, library build, then Python/C++/Fortran/Rust demos; ended with `All demos ran successfully.`

### Quick Demo — Docker path
- **Use Case:** `git clone … && cd jlw_example && make -C docker run-all`
- **What they tried:** Ran the block from a fresh checkout of the working tree, and separately from a literal clone of the public URL.
- **Functionality (working tree):** Succeeded. Built the base image then all runtime images; printed `Hello, Python`, `Hello, C++` (×2), `Hello, Rust`, `Hello, world`.
- **Functionality (public clone):** **Failed.** `make: *** docker: No such file or directory.  Stop.`
- **Expected vs Actual Outcome:** Not met on the public clone, because `docker/` and `.dockerignore` are untracked locally and are absent from `HEAD`/the remote.

## Expected vs Actual Outcome

The three command blocks all work against the current working tree. However, the Quick Demo's literal first step (`git clone https://github.com/terasakisatoshi/jlw_example.git`) does **not** contain the Quick Demo section, the `docker/` directory, or `.dockerignore` — those are uncommitted. A user following the documentation from the published repository therefore:
- sees the old README (no Quick Demo), and
- gets `make: *** docker: No such file or directory` for the Docker path.

This is a shipping/state gap rather than a wording bug: the commands are correct, but the artifacts the docs reference have not been committed/pushed.

## Issues Found

1. **[CRITICAL] The Quick Demo references uncommitted files.** `git ls-tree HEAD -- docker .dockerignore` returns nothing; `git status` shows `docker/`, `.dockerignore`, and `README.md` (Quick Demo) are not in the remote. The documented Docker path cannot work until they are committed and pushed. This is the one blocking issue.
2. **[LOW] The two paths are presented as independent blocks but share the clone directory.** Running the local block and then the Docker block in the same shell makes the second `git clone … jlw_example` fail with `fatal: destination path 'jlw_example' already exists and is not an empty directory`. A reader who tries both sequentially hits an avoidable error.
3. **[LOW] `make` is assumed for the Docker path** and is not listed in the Docker block's prerequisites (it is discoverable from `docker/README.md`).

## Blind-Mode Findings

Not applicable — this run executed the actual documented command sequence (standard mode). The "artifact" under test is the exact shell commands, and the verification gate is their real execution from a fresh checkout.

## Suggestions

1. **Commit and push `docker/`, `.dockerignore`, and the README Quick Demo** so the public clone matches the documentation. This is required before the Docker block is truthful.
2. Make the two blocks explicitly either/or, or use a different directory for the Docker clone (e.g. `git clone … jlw_example && cd jlw_example` for one path, `git clone … jlw_example-docker` for the other), so following both in order does not collide.
3. Add `make` (and Docker) to the Docker block's prerequisites, mirroring the link to 必要環境 in the local block.
4. Consider having CI run the Quick Demo blocks against a fresh checkout, so the docs cannot silently drift from the committed repository again.

## Fixes Applied (review-and-fix)

- **Committed and pushed.** `docker/`, `.dockerignore`, the updated `README.md`, and `docs/test-reports/` were committed as `12add3d` ("Add per-language Docker images, quick demo, and ABI documentation") and pushed to `origin/main`.
- **Re-verified from the real public clone.** A fresh
  `git clone --depth 1 https://github.com/terasakisatoshi/jlw_example.git`
  now contains the Quick Demo section and `docker/`; `make -C docker run-all`
  exited 0 and printed `Hello, Python`, `Hello, C++` (×2), `Hello, Rust`,
  `Hello, world`. The critical issue is resolved.
- **Two paths are now explicitly either/or.** The Quick Demo says the local and
  Docker paths are alternatives, and the Docker block clones into
  `jlw_example-docker` so following both blocks in order no longer collides.
- **Docker prerequisites documented.** The Docker block now states that Docker
  and `make` are required.
